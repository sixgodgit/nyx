# Nyx planning workflow

Before architecture or memory-runtime work, read [PLAN.md](PLAN.md) and the
matching document under [docs/plans](docs/plans/README.md).

- Prioritize completing M1 and language decoupling before implementing M2–M5.
- PLAN.md is the current progress record; design documents describe intended
  behavior, not proof that it has been implemented.
- Preserve existing local work. Check the actual branch and working tree before
  creating or switching branches; the branch names in PLAN.md are planned names.
- Record implementation, verification, host integration and publication
  separately. Do not count overlapping test runs as independent totals.
- Keep language metadata separate from authorization, source trust and user
  response preferences. Preserve original evidence and existing canonical IDs.
- Update relevant task IDs and evidence when completing authorized work. Follow
  the user's current scope for commits, pushes and releases; planning alone is
  not authorization to publish.
