**LANG：语言解耦实施方案**

进度以 [PLAN.md](../../PLAN.md) 为准。实际分支 `codex/language-decoupling` 已从 M1 验证基线 `d78016d` 创建。LANG-00/02 首批交付见[语言适配层与基线结果](../language-adapters.md)；完整语言工作流尚未完成，也未发布新版本。

目标：保持存储、证据、身份、生命周期和协议语义稳定，用语言适配层承接不同表达。第一轮覆盖中英文与混说；不承诺所有语言的理解质量完全一致。

**当前基础与缺口**

- `core/lang.py` 的 NYX_LANG 控制人类界面文字；它不是输入语言，也不是长期回复偏好。
- 画像规则已移入 `language/bilingual.py` 并接入显式适配器；待跟进、完整时间/更正和事件关联仍需 LANG-03 协调。
- LANG-02 已对“花生 / peanuts”等已知、带类型的精确别名生成共同语义键，原始对象和原话保留；未知别名和开放域跨语言检索仍待后续实现。
- `understand.py` 有部分英文句式与关系别名，但当前关系键、实体及句式覆盖存在语言耦合。
- `relevance.py` 支持一些中英分词/词形处理，并对语义、图谱证据另有放行路径；应按实际路径评测。
- 已有可选多语言 embedding；未配置、模型未就绪或质量不足时不能宣称开放式跨语言召回等效。
- LANG-01 已在 M1 分支兼容加入 LanguageContext；详见[语言上下文契约](../language-context.md)。它尚不提供语言别名、时间解析或跨语言更正。

**LANG-00：先冻结基线**

建立开发与留出两套场景，按人物/事件分组防止改写泄漏。分别测输入抽取、当前画像、历史检索、最终证据可见和模型利用，不把画像常驻携带英文原话等同于任意中文查询能找到英文历史。

**LANG-01：语言上下文契约**

在 M1 上兼容增量定义输入语言（允许多语言、mixed、unknown）、用户长期输出偏好、locale、IANA timezone，以及识别依据。区分检测结果与用户明确配置；元数据缺失时维持旧调用。

验收：一句英语不改变长期回复偏好；NYX_LANG 保持原职责；元数据不改变授权、信任、canonical ID。输入/上下文语义变化继续触发请求 ID 或修订变更。

**LANG-02：语言适配层与中性语义键**

将分句、关系、实体别名、否定、时态及偏好更正封装到可插拔规则。采用稳定 predicate/slot/entity 标识，原话及证据片段独立保留。现有中文关系名通过兼容映射读取，不强制重写历史原文和 ID。

验收：同主体、同约束的中英表述可关联；不同主体、不同对象、上下位词不能盲目合并。过敏原等关键对象需要明确别名依据，不能仅凭向量相似度等同。未知语言允许可靠记录，并显式标注理解降级。

**LANG-03：时间与跨语言更正**

使用明确的事件时间、locale、timezone 解释相对日期，保留解析依据。模糊的 `03/04/2026` 在缺少 locale 时保留歧义；定义 next Wednesday 的解析政策。支持否定、取消、改期、历史状态以及跨语言偏好更新。

验收：跨午夜、夏令时、乱序导入可重放；“只改变回复语言”保留其他偏好；旧值不得继续冒充当前状态。无法可靠解析时返回未知/澄清，不猜测永久写入事实。

**LANG-04：跨语言召回**

保留词法精确匹配，加入实体/关系别名映射及可选多语言语义通道，统一通过信任、删除、截止时间和最终预算检查。基础记录确认继续不等待模型。

分别定义两类能力：无向量配置下的结构化关键事实和明确别名查询；真实语义后端下的开放式跨语言相似检索。缺失语义能力时显式降级，不把开启与关闭模型的结果混成一个分数。模型版本、就绪状态、延迟、成本与数据外发设置单独报告。

**LANG-05：呈现语言解耦**

原文、结构化事实、协议字段与最终呈现分开处理。宿主可按用户输出偏好组织回答；需要翻译时引用原始证据，不永久替换原文。元数据、导出标签和 prompt 框架的语言变化不改变事实身份及权限。

**LANG-06：共同验收门禁**

| 维度 | 必测内容 |
| --- | --- |
| 写入语言 → 查询语言 | 中→中、英→英、中→英、英→中及中英混说 |
| 语义与更正 | 否定、取消、改期、过去状态、偏好部分更新、跨语言更正 |
| 主体与实体 | 本人/家人/同事，人名、型号、品牌、邮箱、音译及别名歧义 |
| 表面形式 | 简繁、大小写、词形、数字及中英文标点 |
| 时间 | 事件时间、locale、时区、夏令时、模糊日期、历史导入 |
| 可靠性 | 来源约束、删除/恢复、预算、超时及 M1 请求关联/修订校验在各语言下保持一致；自动修订调度与失效管理由 M2 验收 |
| 后端 | 无向量降级、真实本地多语言模型、可选 API；真实模型评测不得由假 embedding 单测代替 |
| 宿主 | 使用现有文本或启动记忆路径，验证同一关键事实跨语言到达真实最终上下文；语音转写错误与记忆错误分别计量 |

先报告基线再冻结质量门槛，分别公开各组合结果。LANG 完成不要求尚未实现的 M2 逐轮语音调度。M1 与 LANG 共同验收后放行 M2；语言元数据为 M2 ASR 修订及 M3 实体本体复用，避免再次以词面充当身份。
