**M5：多设备与生态实施方案**

进度以 [PLAN.md](../../PLAN.md) 为准；当前仅规划。计划分支：`codex/m5-ecosystem`。执行前置：核心路径稳定且存在真实跨设备需求。

目标：让一位所有者在明确共享作用域下复用记忆，维持本地默认和精简核心。

| 子任务 | 实施方案 | 验收 |
| --- | --- | --- |
| M5-01 | 设备身份、档案、共享范围与能力协商 | 设备和第三方不能凭内容/session ID 提升访问权限 |
| M5-02 | 可选本地 daemon、稳定 SDK 和版本化协议 | 单进程 Python/Hermes/MCP 调用继续可用；网络/机器人/模型依赖保持可选 |
| M5-03 | 定义权威端、离线队列、幂等同步、缓存失效和冲突处理 | 断线/重连/重试可对账；删除不被旧副本重建，未知状态如实报告 |
| M5-04 | 真实设备矩阵、升级与小范围发布 | 跨设备验证权限、版本、延迟、保留及回退，提供可恢复迁移 |

先依据真实设备数量、离线时长和延迟需求选择拓扑，再决定是否需要远程服务。原始媒体同步必须可选，内容去重不能突破授权或保留范围。

删除失效区分 Nyx 管理的本地/缓存数据与已发送到外部模型或第三方的副本；不得宣称所有外部内容已经撤回。对备份、导出与设备丢失明确恢复和保留边界。

升级协调包、插件、SDK 与宿主能力，使用真实安装环境验证。协议版本、适配器兼容矩阵及发布前检查随目标宿主更新。
