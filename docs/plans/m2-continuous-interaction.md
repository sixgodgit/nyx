**M2：连续交互实施方案**

进度以 [PLAN.md](../../PLAN.md) 为准；当前仅规划。计划分支：`codex/m2-continuous-interaction`。执行前置：M1 与 LANG 共同验收。

目标：让相关记忆在宿主支持的时机自动进入当前任务/对话，并验证它实际被应用。

2026-11-26 已补充 [跨厂商实时语音接入调查与方案](m2-voice-memory.md)：核对当前手机、桌面与插件源码，
区分开场记忆、模型工具调用、自动转写调度与生成前闸门。现有插件相关测试 297 项通过；
新增统一调度器尚未实现，用户实际部署及真机语音效果未据此验证，不改变本阶段的前置与进度。

| 子任务 | 实施方案 | 验收 |
| --- | --- | --- |
| M2-01 | 有界工作记忆保存任务、指代、场景版本、未完成事项和已注入证据 | 跨任务隔离，重启/结束生命周期明确，长期回放可重现 |
| M2-02 | 稳定转写片段触发预取，协商启动/回答前/会话追加等宿主能力 | 在一个真实支持的客户端验证，不能仅用 HTTP 成功代替真机效果 |
| M2-03 | 维护最新 session/turn/revision，处理取消、场景变化和遗忘失效 | 迟到结果与旧修订不跨轮应用；不把 M1 的关联检查称作自动调度 |
| M2-04 | 最终转写、修订、重试、断线和通话结束归档共享幂等身份 | 原始输入可审计，多次投递不导致重复晋升，归档能对账 |
| M2-05 | 记录生成/发送/应用确认，跟进策略有偏好、去重及冷却 | 回答引用正确证据，误跟进与无关注入可量化；不推断未观测到的模型利用 |

ChatGPT 订阅 GPT-Live 与公开 Realtime API 分开建能力矩阵。无法暂停回答时明确采用追加、下一轮生效或澄清策略，不能承诺每次回答前召回完成。临时 ASR delta 留在短期状态；稳定修订按明确规则落盘。

对照固定模型、工具、token 和记忆数据，分别评测必要事实可见率、过时事实使用、无关注入、迟到应用、跟进打扰、转写错误和端到端延迟；包含中英四向及混说。

功能按宿主 capability 开关；调度异常时退回已验证的启动记忆/显式查询，并保留幂等对账数据。M3 复用任务与状态版本接口，独立验证动态环境收益。
