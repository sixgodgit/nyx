**恢复与兼容政策**

- 保留用户原始证据、canonical IDs、来源和墓碑。投影视图可重建，不能充当原始记录权威。
- StoreContext 的根与凭证由可信宿主选定；session/task/query 文本不能切换根。默认单用户进程维持旧入口。
- 对旧记录的正文、删除状态和来源信任更新，与投影失效标记同事务；中断后重新处理，不依赖进程内回调。
- 批次写入与 checkpoint 同事务，旧 worker 不能提交到新租约或新版本。失败状态仅保存稳定错误码。
- 回滚程序需保留已确认的新写入。不可用旧备份覆盖新事件；事务账本权威切换另立设计、影子比对与故障注入任务。

**验收覆盖**

既有契约/编排/宿主测试覆盖完整证据、关键限制、重复/乱序关联、截止时间、预算、来源、删除与恢复。新增 `test_store_context.py` 验证同进程双档案真实闭环、线程池复用、配置与凭证隔离、历史导入、时钟、开关及媒体清理边界。`test_projection_jobs.py` 验证批次回滚、真实进程异常退出、重启重试、版本变更、竞争租约及恢复旧记录时没有回调的场景。

不把多个重叠测试运行累加成新的全量数；Python 版本、真实宿主集成、wheel 和发布流水线各自登记。最终发布只在门禁通过后执行，GitHub Release/Actions 是外部发布结果的依据。
