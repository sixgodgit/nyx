**Typed recall contracts — M1, first increment**

Nyx now offers `RecallRequest`, `EvidenceRef`, `ContextPacket` and
`recall_request()` from `nexsandglass.runtime`. This is an additive API over the
existing recall planner, trust gate, ranking and token estimator. It creates no
second memory engine and does not migrate storage or change `recall(str)`.

```python
from time import monotonic
from nexsandglass.runtime import RecallRequest, recall_request

request = RecallRequest(
    query="Where was that cup?",
    context="The current task concerns the blue cup in the kitchen.",
    session_id="session-1",
    turn_id="turn-8",
    revision=0,
    task_id="find-cup",
    channel="agent",
    token_budget=600,
    deadline=monotonic() + 0.2,
)
packet = recall_request(request)

# An asynchronous host must use ITS CURRENT request, which may have changed
# while recall was running. Do not always pass the old request back here.
current_request = request
if packet.can_apply_to(current_request):
    context_text = packet.text
    transport_payload = packet.to_dict()
```

The 200 ms deadline in this example is a caller-selected collection budget,
not a measured latency claim or a hard real-time guarantee.

**Request semantics**

- `query`, `context`, `token_budget` and `session_id` reach the same existing
  recall implementation. Context expansion retains its current anaphora,
  secret-filtering and length rules.
- `request_id` is generated by default. Session/turn/revision/task/scene/channel
  fields correlate work; they do not authenticate a principal, select a data
  directory, authorize sharing or add persistent database filters. The host
  still selects its existing profile/store before calling Nyx.
- A semantic query or task-context change requires a new request ID or a new
  revision. The packet does not export query/context or their fingerprints.
- Optional `language=LanguageContext(...)` separates input language, explicit
  response preference, locale and timezone. It defaults to `None`; no detection,
  translation or persistent preference change happens when it is passed.
  Language does not select storage or grant trust. See
  [the language-context contract](language-context.md).
- Budgets/revisions are nonnegative integers; identifiers are bounded text;
  NaN, infinity, booleans and invalid deadline values are rejected. Query and
  context are excluded from the request repr, not from the request object.
- `deadline` is an absolute `time.monotonic()` timestamp local to this process.
  A network adapter must translate a duration into its own local deadline; it
  must not forward another process's monotonic timestamp.
- A request supplied to the internal planner is authoritative over its legacy
  query/budget/context/session arguments. Public typed consumers should call
  `recall_request(request)` to avoid mixing these forms.

**Deadline and application semantics**

An already-expired request returns an empty `expired` packet without submitting
sources. Otherwise each source deadline is capped by the request deadline.
Successful earlier evidence may survive as a partial result, but any packet
that exceeded the request deadline has `deadline_exceeded=True` and cannot pass
`can_apply_to()`.

Preprocessing, local database operations and rendering cannot be forcibly
preempted by Python. The deadline is checked again after evidence binding.
Downstream I/O retains its own timeout; running late sources retain their
capacity slot until completion. This increment adds no global revision broker,
automatic cancellation, or hard real-time execution guarantee.

`matches_request()` checks correlation fields, token budget and optional language
context. `can_apply_to()`
also rejects expired/error results, expired local deadlines, candidate-stage
packets and results exceeding the current budget. Hosts supply their latest
request and remain responsible for invalidation after later forgetting or
world-state changes. A match is not proof that stored facts are still current
or that a model has applied them.

**Evidence and export boundary**

- Each `EvidenceRef` retains the retrieval alias (`memory_id`) separately from
  a verified raw-record binding (`source_mem_id`). Existing ID formats stay
  unchanged.
- A numeric source ID on a retrieved object denotes `line_start`, not sequence
  number. Binding uses an explicit database lookup by journal line, including
  ambiguity/deletion checks; it never guesses a canonical ID from content.
- Explicit journal sources that are missing, deleted, ambiguous or unavailable
  at export are omitted from both text and evidence, with `source_unavailable`.
  Other valid results survive. This rechecks stale indexes and deletion between
  retrieval and export; it does not make a returned snapshot perpetually valid.
- Generated information with no journal line can remain present with an
  unresolved binding and `unknown` trust. Existing projections do not yet all
  provide complete dependency lineage. No instruction authority or calibrated
  probability is inferred from a trust label or retrieval score.
- Only retained objects supply packet text/references. Internal trace items,
  withheld payloads, raw exception strings, query and task-context text are not
  copied into the exported metadata. Error responses use stable reason codes.
- `ContextPacket` and `EvidenceRef` are frozen, and collections are copied into
  tuples. `to_dict()` returns a detached export suitable for JSON encoding.
  Optional language metadata is also frozen; its nested dictionary is detached.
  Packets without language metadata omit that key to preserve the old shape.
  Do not serialize an entire legacy `MemoryContext`: its debug traces can
  contain pre-filter candidates and backend exception details.
- Public `recall_request()` returns stage `context`. An internal planner call
  with `candidate_mode=True` may carry stage `candidates`, deliberately retaining
  evidence before a host's final relevance/rendering budget. Its content can
  exceed the final budget and `can_apply_to()` always rejects that stage.

Packet status is `ready`, `empty`, `partial`, `expired` or `error`. The inherited
legacy `degraded` flag can also reflect an empty result or a policy-disabled
source, so it is not by itself a failure classification. `schema_version=1`
versions the packet representation; no network endpoint is added here.

**Compatibility and next increments**

Legacy calls still return `MemoryContext`, with an optional `packet` field used
only by typed calls. Hermes prefetch and voice startup remain on their existing
paths. In particular, voice startup still reads the dedicated profile/follow-up
capability rather than generic query recall.

Subsequent increments will unify final host rendering budgets, adopt this
contract in host adapters, introduce explicit `StoreContext`, and implement
working-memory revision/invalidation scheduling. Transaction-ledger migration,
world-state modeling and action learning are separate milestones.

M1-02 now adds [shared final-context composition](context-composition.md) and
adopts it in MemoryBundle and the Hermes per-turn packing helpers. Host-wide
system/prefetch budget coordination and full adapter adoption remain M1-03.

Behavioral tests in `tests/test_m1_contracts.py` cover real multiline record
binding, deletion/ambiguity, trust/budget export, request deadlines, correlation,
immutable exports, input validation, safe failures and legacy compatibility.
